Base URL: your deployment's origin, for example `https://notify.example.com`

| Method | Path         | Auth   | Purpose                              |
| ------ | ------------ | ------ | ------------------------------------ |
| `GET`  | `/healthz`   | none   | Liveness check                       |
| `POST` | `/v1/notify` | Bearer | Post one notification to a target    |

Any other path returns `404 not_found`. A wrong method on a known path returns `405 method_not_allowed` with an `Allow` header.

## GET /healthz

```sh
curl https://notify.example.com/healthz
```

```json
{ "ok": true, "service": "zudo-slack-notify" }
```

The response carries `X-Request-Id`. It does not check secrets or Slack: a Worker that has not been wired still answers `200` here. Non-GET methods return `405` with `Allow: GET`.

## Common response headers

Every JSON response carries `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, and `X-Request-Id` (the same UUID as `requestId` in the body).
