The examples use `https://notify.example.com` as the origin. Substitute your own custom domain or `workers.dev` hostname.

## Check the Worker is up

```sh
curl https://notify.example.com/healthz
# {"ok":true,"service":"zudo-slack-notify"}
```

## Create the sender env file

A sender needs two values: the endpoint URL (your origin plus `/v1/notify`) and the relay key. It never needs the Slack bot token. Put them in a file **outside the repository**, for example `"$HOME/.config/zudo-slack-notify/sender.env"`:

```sh
ZUDO_SLACK_NOTIFY_URL=https://notify.example.com/v1/notify
ZUDO_SLACK_NOTIFY_API_KEY=<your-relay-key>
```

Keeping it outside the checkout means it can never be committed by accident. Restrict it to your user, for example with `chmod 600`.

## Dry run

A dry run validates and renders the message locally and prints the request plus the Slack payload it would produce. No network is used and no env file is needed.

```sh
cd app
node cli/notify.ts --file examples/simple.json --dry-run
```

## Send it

Load the sender env file with `node --env-file` so the key never appears on the command line:

```sh
node --env-file="$HOME/.config/zudo-slack-notify/sender.env" \
  cli/notify.ts --target dev --message "Hello from zudo-slack-notify." --kind success
```

Use one of the aliases you put in `SLACK_TARGETS`. Success exits `0` and prints a receipt:

```json
{
  "ok": true,
  "delivery": "sent",
  "requestId": "…",
  "target": "dev",
  "channel": "C0123456789",
  "ts": "1750000000.000001"
}
```

If it fails, the exit code and `error.code` tell you why. See the [error catalog](../../api/errors/) and [Troubleshooting](../../operations/troubleshooting/). A `503 server_misconfigured` means one of the three Worker secrets is missing or malformed.

From here, see the [CLI](../../cli/) for every flag, [POST /v1/notify](../../api/notify/) to call the API from your own code, and the [Agent skill](../../agent-skill/) to let an agent send notifications.

:::note[If you deploy with GitHub Actions]
The "Deploy app" workflow's smoke check accepts `503 server_misconfigured` from `POST /v1/notify` until Slack is wired. After this first message is delivered, set the repository variable `SLACK_WIRED=true` (for example `gh variable set SLACK_WIRED --body true`) so a later `503` fails the run instead. See [Secrets and rotation](../../operations/secrets/) for details, including when to add `[secrets] required` to `app/wrangler.toml`.
:::
